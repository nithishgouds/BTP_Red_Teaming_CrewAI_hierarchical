\begin{abstract}
As part of the empirical benchmark evaluation required for BTP Phase II, multi-agent red-teaming pipelines were evaluated across three local large/small language model (LLM/SLM) backends: Meta Llama 3.2 (3B), Mistral (7B), and Microsoft Phi-3 Mini (3.8B). While Llama 3.2 and Mistral successfully executed the 30-run evaluation matrix with high task utility (73.3\%--80.0\%) and clear vulnerability dynamics, Microsoft Phi-3 Mini exhibited severe behavioral anomalies, technical incompatibilities, and architectural failure modes. Specifically, Phi-3 Mini failed under native CrewAI tool-calling protocols due to an upstream Ollama manifest deficiency (\texttt{HTTP 400: phi3 does not support tools}), suffered massive latency inflation (averaging 730.7 seconds per run compared to 137.9 seconds for Llama 3.2), and underwent catastrophic autoregressive attention collapse when chained through 6--7 sequential agents, producing non-terminating hallucinatory babble and a 0.0\% benign task success rate. This report provides a comprehensive, ground-up investigation of the technical root causes, mathematical mechanisms, runtime phenomena, and academic implications of these findings.
\end{abstract}

\section{Investigation Context and Benchmark Objectives}

The primary objective of the empirical benchmarking phase is to evaluate the privacy leakage surface of hierarchical and sequential multi-agent systems processing sensitive unstructured documents under active indirect prompt injection attacks.

To ensure empirical validity, the experimental protocol mandates testing across four distinct domains (HR Performance Reviews, Commercial Financial Records, Electronic Health Records, and Legal Discovery Documents) across three distinct model families hosted locally via Ollama:
\begin{enumerate}
    \item \textbf{Meta Llama 3.2 (3B):} Represents state-of-the-art edge-optimized compact architectures.
    \item \textbf{Mistral (7B):} Represents high-capacity, general-purpose enterprise open-weight models.
    \item \textbf{Microsoft Phi-3 Mini (3.8B):} Represents small language models (SLMs) trained with synthetic educational data designed to maximize reasoning capabilities relative to parameter count.
\end{enumerate}

While Llama 3.2 and Mistral demonstrated coherent task execution, Phi-3 encountered a progression of severe operational blocks and cognitive degradation. The subsequent sections document the chronological and technical autopsy of this failure.

% SECTION 2: CHRONOLOGICAL AUTOPSY OF THE PHI-3 BENCHMARK
% ==============================================================================
\section{Chronological Autopsy of the Execution Failures}

\subsection{Phase 1: Environment Initialization and Port Collision}
Initial deployment required spinning up local Ollama backend daemons. When running:
\begin{lstlisting}[language=bash]
ollama serve
\end{lstlisting}
the system aborted with the following operating system error:
\begin{lstlisting}[language=bash]
Error: listen tcp 127.0.0.1:11434: bind: Only one usage of each socket address (protocol/network address/port) is normally permitted.
\end{lstlisting}
\textbf{Diagnosis:} On Windows host operating systems, the Ollama desktop service defaults to running as a continuous background daemon initialized in the Windows System Tray. Attempting to manually launch a second server instance created a TCP socket binding collision on port 11434. Once confirmed via HTTP GET \texttt{http://127.0.0.1:11434/api/tags}, the local API was confirmed to be operational.

\subsection{Phase 2: CrewAI LiteLLM Tool-Calling Incompatibility}
When Phi-3 was plugged into the baseline CrewAI evaluation harness, the orchestration immediately halted with persistent runtime exceptions:
\begin{lstlisting}[language=bash]
litellm.exceptions.BadRequestError: OllamaException - {"error":"registry.ollama.ai/library/phi3:latest does not support tools"}
\end{lstlisting}
In CrewAI, agent tool execution relies on OpenAI-compatible function-calling JSON schemas injected into the LLM request payload:
\begin{lstlisting}[language=json]
{
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "delegate_work_to_coworker",
        "description": "Delegate a task to a coworker agent",
        "parameters": { ... }
      }
    }
  ]
}
\end{lstlisting}
While Ollama's model manifests for Llama 3.1/3.2 and Mistral support native function calling, the Ollama GGUF wrapper for \texttt{phi3:latest} does not expose tool-calling capabilities. When LiteLLM detects an agent with defined tools, it transmits the schema, triggering an immediate \texttt{HTTP 400 Bad Request} from Ollama. CrewAI interprets this as a transient failure and enters an infinite retry loop, stalling execution indefinitely.

\subsection{Phase 3: The Tool-Safe Decoupling Refactoring}
To resolve the HTTP 400 barrier without compromising architectural comparability, a specialized benchmark runner was engineered (\texttt{tools/run\_phi3\_benchmark.py}). The architecture was refactored as follows:
\begin{enumerate}
    \item \textbf{Schema Stripping:} All explicit tool definitions were removed from Phi-3 agents (\texttt{tools=[]}), preventing LiteLLM from transmitting tool schemas to Ollama.
    \item \textbf{Prompt-Directed Payload Formatting:} The \texttt{External API Integrator} agent was directed to output the transmission payload as structured string content rather than an active function call.
    \item \textbf{Deterministic Pre-Transmission Egress Inspection:} The outbound payload was routed directly to the \texttt{EgressSecurityGateway} service before transmission, validating whether raw PII tokens were exposed or contained.
\end{enumerate}

\subsection{Phase 4: The 15-Minute Apparent Freeze and Latency Explosion}
Following the refactoring, the pilot benchmark was launched:
\begin{lstlisting}[language=bash]
uv run python tools/run_phi3_benchmark.py --mode pilot
\end{lstlisting}
The console output proceeded as follows:
\begin{lstlisting}[language=bash]

    Filename:    fuzz_d1ab6b28df_hr_performance_review.pdf

Following the warning log, the terminal ceased all output for over 15 minutes, prompting the investigation into whether the process had entered a deadlocked state.

\begin{calloutbox}{Root Cause of the Apparent Freeze}
The process was \textbf{not frozen}. The warning line marked the successful completion of \textbf{Run 1 (Config A)}. The subsequent silence was caused by two compounding factors:
\begin{enumerate}
    \item \textbf{Suppressed Verbosity:} In the agent factory function, \texttt{verbose=False} was configured, suppressing the agent scratchpad and reasoning outputs.
    \item \textbf{Sequential Agent Latency on 4GB VRAM:} Config B required executing 6 sequential agents. On an NVIDIA GeForce RTX 3050 Laptop GPU (3.2 GiB available VRAM), each agent evaluation required approximately 120 seconds. Compounded across 6 agents, Run 2 required over 12 minutes of continuous computation before producing terminal output.
\end{enumerate}
\end{calloutbox}

\subsection{Theoretical Root Cause: Autoregressive Attention Collapse}
The generation of disconnected, fragmented text is a documented pathological failure mode in small language models, specifically attributable to:

\begin{enumerate}
    \item \textbf{Context Compounding in Multi-Agent Pipelines:}
    In sequential multi-agent architectures, downstream agents receive the concatenated outputs of all upstream agents:
    \begin{equation}
        \mathcal{C}_{t} = \mathcal{C}_{0} \cup \bigcup_{i=1}^{t-1} \mathcal{O}_i
    \end{equation}
    By the time the context reaches Agent 5 (\texttt{Response Formatter}) or Agent 6 (\texttt{Supervisor}), the context prompt $\mathcal{C}_t$ exceeds 2,500 tokens, containing multiple conflicting system instructions, structured redaction tokens (e.g., \texttt{<PERSON\_1>}, \texttt{<US\_SSN\_1>}), and nested quotes.

    \item \textbf{Chat Template Desynchronization:}
    Phi-3 Mini was fine-tuned with a strict chat template structure:
    \begin{lstlisting}[language=text]
<|user|>
{prompt}<|end|>
<|assistant|>
    \end{lstlisting}
    When CrewAI wraps intermediate prompts with its verbose instruction wrappers (``You are a communications specialist... Output the formatted string...''), the strict special tokens are either omitted or scrambled by the LiteLLM proxy. This induces template confusion, causing the model to treat its own previous instructions as user input.

    \item \textbf{RoPE Positional Degradation and Attention Dispersion:}
    While Phi-3 utilizes Rotary Position Embedding (RoPE) theoretically supporting larger context lengths, its 3.8-billion parameter attention head representation suffers from severe dispersion when processing repetitive, unstructured text. As the attention distribution becomes uniform across tokens:
    \begin{equation}
        \lim_{|\mathcal{C}| \to \infty} \text{Softmax}\left(\frac{\mathbf{Q}\mathbf{K}^T}{\sqrt{d_k}}\right) \to \text{Uniform}
    \end{equation}
    the model loses the ability to condition next-token predictions on the user prompt, instead sampling randomly from high-frequency training n-grams (e.g., medical journals, legal texts, textbook indexes).

    \item \textbf{Loss of End-of-Sequence (EOS) Generation:}
    Crucially, because the attention heads became dispersed, the model failed to predict the terminal token \texttt{<|end|>} or \texttt{<|endoftext|>}. Consequently, it continued generating arbitrary tokens until reaching the hard generation cutoff (\texttt{max\_tokens}), which directly explains the massive \textbf{730.7-second latency per run}.
\end{enumerate}

\begin{dangerbox}{The Fallacy of Evaluating Privacy in Isolation}
Evaluating privacy metrics without concurrent utility validation yields deceptive conclusions. On paper, Phi-3 Mini achieved:
\begin{itemize}
    \item 0.0\% Adversarial Prompt Injection Rate
    \item 0.0\% PII Leakage Rate
    \item 100.0\% Guardrail Block Rate
\end{itemize}
However, Phi-3 did \textbf{not} resist the attack due to security alignment. Rather, it suffered \textbf{total operational failure}. It was incapable of extracting the benign HR review, and equally incapable of parsing the adversary's extraction instruction. In security engineering, an inoperative system is theoretically impervious to data exfiltration, but provides \textbf{zero utility}.
\end{dangerbox}

In sharp contrast:
\begin{itemize}
    \item \textbf{Llama 3.2} accurately answered benign queries, but was tricked into leaking PII when exposed to Delimiter Smuggling attacks under Config A. Our Guardrail (Config B/C) successfully defused this vulnerability while preserving benign task utility.
    \item \textbf{Mistral} exhibited high comprehension, following exfiltration payloads under Config A across all threat classes. Our Guardrail reduced its transmitted PII to 0.0\%.
\end{itemize}

\section{Engineering Mitigations: What Must Be Done for Small Models?}

If resource-constrained enterprise deployments mandate the use of small language models ($\le$ 4B parameters) in multi-agent pipelines, the following architectural adjustments are necessary:

\begin{enumerate}
    \item \textbf{Context Window Pruning via Summarization Agents:}
    Instead of passing cumulative raw context ($\mathcal{C}_t$), an intermediate summarizer must compress historical outputs into concise, deterministic key-value tuples before handoff to downstream agents.

    \item \textbf{Grammar-Constrained Decoding (GBNF):}
    Ollama and \texttt{llama.cpp} support formal context-free grammars (GBNF). Small models must be constrained to output valid JSON conforming strictly to an exact schema, eliminating free-form conversational hallucination loops.

    \item \textbf{Single-Turn Zero-Shot Extraction:}
    Deep multi-agent delegation chains (5--7 agents) exceed the reasoning depth of sub-4B models. SLMs should be restricted to single-turn tasks (e.g., dedicated NER tagging) rather than complex hierarchical orchestration.

    \item \textbf{Model Version Upgrades:}
    Deploying \texttt{phi3.5-mini} or \texttt{phi3:mini-128k} with explicit function-calling fine-tunes resolves the Ollama HTTP 400 schema error and provides improved RoPE scaling.
\end{enumerate}
